4. Diagrama de secuencia — Emisión de factura

Flujo de generación de factura: lee consumos del período, aplica tarifas progresivas y persiste el documento.

sequenceDiagram
    autonumber
    participant CLI as Cliente HTTP
    participant CTRL as FacturaController
    participant FSVC as FacturaService
    participant LSVC as LecturaService
    participant TSVC as TarifaService
    participant FJPA as FacturaRepository
    participant DB as PostgreSQL

    CLI->>CTRL: POST /api/facturas/generar
{clienteId, periodo}
    CTRL->>CTRL: Validar DTO (Jakarta)
    CTRL->>FSVC: generarFactura(clienteId, periodo)
    activate FSVC
    FSVC->>LSVC: obtenerLecturasPeriodo(medidor, periodo)
    activate LSVC
    LSVC->>DB: SELECT lecturas del período
    DB-->>LSVC: lista de lecturas
    LSVC-->>FSVC: lecturas + consumo total (m3)
    deactivate LSVC
    FSVC->>TSVC: calcularImporte(consumo, fecha)
    activate TSVC
    TSVC->>DB: SELECT tarifas vigentes
    DB-->>TSVC: tramos progresivos
    TSVC-->>FSVC: cargoFijo + subtotal + total
    deactivate TSVC
    FSVC->>FSVC: arma objeto Factura (estado=PENDIENTE)
    FSVC->>FJPA: save(factura)
    FJPA->>DB: INSERT INTO factura
    DB-->>FJPA: factura persistida
    FJPA-->>FSVC: Factura
    FSVC-->>CTRL: FacturaDTO
    deactivate FSVC
    CTRL-->>CLI: 201 Created + body

5. Diagramas de secuencia — Lectura y Pago

5.1 Registro de lectura con cálculo de consumo

sequenceDiagram
    autonumber
    participant OPC as Operador / API
    participant LC as LecturaController
    participant LS as LecturaService
    participant MR as MedidorRepository
    participant LR as LecturaRepository
    participant DB as PostgreSQL

    OPC->>LC: POST /api/lecturas
{medidorId, valor, fecha}
    LC->>LS: registrar(dto)
    activate LS
    LS->>MR: findById(medidorId)
    MR->>DB: SELECT medidor
    DB-->>MR: medidor
    LS->>LR: ultimaLectura(medidorId)
    LR->>DB: SELECT ultima lectura
    DB-->>LR: lectura anterior
    LS->>LS: consumo = valor - anterior
    alt consumo < 0
        LS-->>LC: 409 Error relectura inválida
    else consumo válido
        LS->>LR: save(lectura)
        LR->>DB: INSERT INTO lectura
        DB-->>LR: OK
        LS-->>LC: LecturaDTO con consumo
    end
    deactivate LS
    LC-->>OPC: 201 Created

5.2 Registro de pago y actualización de factura

sequenceDiagram
    autonumber
    participant CAJ as Caja / API
    participant PC as PagoController
    participant PS as PagoService
    participant FR as FacturaRepository
    participant PR as PagoRepository
    participant DB as PostgreSQL

    CAJ->>PC: POST /api/pagos
{facturaId, monto, metodo}
    PC->>PS: pagar(dto)
    activate PS
    PS->>FR: findById(facturaId)
    FR->>DB: SELECT factura
    DB-->>FR: factura
    PS->>PS: validar estado PENDIENTE/VENCIDA
    PS->>PR: save(pago)
    PR->>DB: INSERT INTO pago
    DB-->>PR: pago
    PS->>PR: sumPagos(facturaId)
    PR->>DB: SELECT SUM(monto)
    DB-->>PR: totalPagado
    alt totalPagado >= factura.total
        PS->>FR: factura.estado = PAGADA
        FR->>DB: UPDATE factura
    else parcial
        PS->>PS: factura queda PENDIENTE
    end
    PS-->>PC: PagoDTO + estado factura
    deactivate PS
    PC-->>CAJ: 201 Created

Reglas de negocio clave

#Regla
1Consumo = lectura actual − lectura anterior; si el resultado es negativo, se rechaza (relectura / anulación).
2Facturación progresiva: el consumo se reparte por tramos de tarifa vigente a la fecha del período.
3Solo un medidor activo por toma; al cambiar medidor se cierra el anterior con lectura de cierre.
4Factura queda PAGADA cuando SUM(pagos) ≥ total; admite pagos parciales.
5Facturas con vencimiento superado y sin pago total pasan a estado VENCIDA.
6Una toma se da de baja solo si su medidor no tiene lecturas pendientes del período.
